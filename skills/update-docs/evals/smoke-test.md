# Smoke test: a real whole-repo audit on CtrlCarlitos/dotfiles

Read-only verification against real, messy documentation -- kept separate
from the synthetic fixtures in `evals.json`, which exist to exercise
specific, constructed edge cases. This run instead checks that
`scripts/gather.py` behaves correctly against docs nobody built to be a
test fixture, with all three optional tools (`markdownlint-cli2`,
`lychee`, `vale`) actually installed and actually invoked.

## Run

```bash
git clone https://github.com/CtrlCarlitos/dotfiles   # read-only, no push
cd skills/update-docs
python3 -m scripts.gather <path-to-dotfiles-clone> --scope repo
```

## Result (2026-10-18)

- Repo type: `generic` (built-in default -- dotfiles has no
  `__manifest__.py`, `mix.exs`, `go.mod`, or Flutter `pubspec.yaml`).
- 37 tracked doc files discovered (`AGENTS.md`, `SECURITY.md`,
  `docs/*.md`, etc.), all in scope for a whole-repo audit; its real
  `CHANGELOG.md` and any ADR-style paths were correctly never surfaced
  at all (Rule 6), confirming the exclusion happens at discovery, not
  just at edit time.
- One real true positive for `is_generated()`: `docs/tool-parity.md`
  contains `<!-- tool-parity:packages-begin (generated by
  scripts/gen-tool-parity.sh from .chezmoidata/packages.yaml - do not
  edit by hand; rerun the script) -->` around one table. The rest of
  that same file is ordinary hand-written prose -- a real example of the
  "partial generation" case now called out explicitly in `SKILL.md`'s
  Rule 4 section (this was added *because* of what this smoke test
  found, not written speculatively).
- `markdownlint`: ran, found real issues (dotfiles' docs don't run
  markdownlint in CI, so this was expected).
- `lychee`: ran, found 2 broken links -- both `npmjs.com` URLs returning
  HTTP 403. Checked manually: this is npm's site blocking automated
  requests, not a genuinely dead link. Documented as a caveat in
  `SKILL.md` ("spot-check a `broken` entry... if the status looks like
  bot-blocking rather than a real 404/DNS failure") directly because of
  this finding.
- `vale`: ran against the built-in Google style (dotfiles has no
  `.vale.ini` of its own), found 4,282 findings dominated by
  `Google.Parens`, `Google.Semicolons`, `Google.Acronyms`,
  `Google.Passive`, `Google.Contractions` -- expected, since dotfiles
  was never written to the Google developer-documentation style. This
  is exactly why `check_prose`'s `passed` is a simple "zero findings"
  boolean rather than an attempted quality gate: judging which of 4,282
  style suggestions are worth acting on is the agent's call during an
  actual Audit-mode run, not something to pre-filter mechanically.

No writes were made to the dotfiles clone; `gather.py`'s own read-only
guarantee is additionally covered by the `audit-mode-leaves-the-repo-
unchanged` fixture in `evals.json` (asserts `git status`/`HEAD` are
byte-identical before and after a real `gather()` call). The clone was
discarded after this run.
