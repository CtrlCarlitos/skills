# Repo type: docs

For a repo that *is* documentation (a docs site's own source), not a
code repo with docs attached. No reliable file signature either --
select it explicitly, like `course`.

## Where docs live

Everywhere -- the whole tree (minus site-generator config and assets) is
documentation. Check the site generator's config (`mkdocs.yml`,
`docusaurus.config.js`, `_config.yml`, `book.toml`) for the actual
content root and navigation structure.

## What's generated, and by what

The built site output (`_site/`, `build/`, `.vitepress/dist/`, etc.) is
always generated by the site's own build command -- never audited or
edited directly; audit the source Markdown/MDX/RST instead.

## What's public (must be documented)

Everything in the nav/sidebar config is, by definition, meant to be
read. A page that exists but isn't linked from anywhere is itself a
finding worth surfacing (orphaned content).

## "Don't document" markers

A page explicitly marked draft/unlisted in its front matter (common
keys: `draft: true`, `unlisted: true`, `hidden: true`).

## Breaking vs. routine for docs purposes

A moved or renamed page breaks inbound links and search results --
that's the main "breaking change" this type cares about. Flag it even
without a redirect check, since this skill doesn't crawl external
backlinks; note what moved and let a person decide whether a redirect is
needed.
