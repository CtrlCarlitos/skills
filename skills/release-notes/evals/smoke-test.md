# Smoke test: a real range on CtrlCarlitos/dotfiles

Read-only verification against real, messy history -- kept separate from
the synthetic fixtures in `evals.json`, which exist to exercise specific,
constructed edge cases. This run instead checks that `scripts/gather.py`
behaves correctly against history nobody built to be a test fixture.

## Run

```bash
git clone https://github.com/CtrlCarlitos/dotfiles   # read-only, no push
cd skills/release-notes
python3 -m scripts.gather <path-to-dotfiles-clone> --base v2026.10.05 --head v2026.10.09
```

- Range resolved: `v2026.10.05..v2026.10.09` (`head_sha`
  `57c3dfb209b19b3773b34cc4428e33a252114dae`).
- 77 commits gathered, 0 excluded as reverted pairs.
- Repo type: `generic` (built-in default — dotfiles has no `__manifest__.py`,
  `mix.exs`, `go.mod`, or Flutter `pubspec.yaml`).
- Existing changelog found at `CHANGELOG.md`, correctly flagged
  `generated: true` — it says "Generated by `scripts/changelog.sh` from
  git history - do not edit by hand." A real SKILL.md run against this
  repo must stop instead of hand-editing it, exactly as step 5 says.
- One real-world case worth recording: commit #266's subject is
  `revert(upgrade): Windows goes back to the Claude Code installer...` —
  a human-chosen Conventional Commits type, not an actual `git revert`.
  It correctly stayed in `commits` (not collapsed into `not_included`),
  because `collapse_reverted_pairs` only matches a real
  `This reverts commit <sha>.` trailer in the commit body, never a
  commit's chosen label. Mirrors the "commit type never hides a change"
  rule from SKILL.md step 2, in the other direction: a *label* claiming
  to be a revert doesn't make it one either.
